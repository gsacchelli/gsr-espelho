## Decisões fechadas com Gustavo antes de codar

### Prazo por item
- **Local**: card do item individual (não Setup global)
- **Tipo**: input numérico em dias
- **Display**: vazio→"A combinar"/"To be confirmed", 0→"Pronta entrega"/"Ready stock", N≥1→"N dias"/"N days"
- **Persistência**: via `SIM_SAVE_FIELDS` no state do pacote (snapshots legados sem o campo caem no fallback)

### Descrição pra Proposta
- **Comportamento**: auto-gerada do label técnico, editável (vendedor edita só quando quer texto comercial diferente)
- **Detecção edição manual**: flag `_descPropAuto` desconecta após edição. Mesma mecânica do Mercosul (Fase 4f) e VPP (Camada 11)
- **Reversão**: botão "↻ auto" volta pra geração automática
- **Modo export EN**: NÃO traduz texto custom (responsabilidade do vendedor); só fallback de campos traduz perfil/acab via `I18nProposta`

## Entregas

### 1. `js/schema_proposta.js` — função pura `formatPrazoDias`

```js
formatPrazoDias(diasRaw, lang='pt') → string
```

Aplica regra de display do Prazo. Fallback defensivo: negativos/inválidos retornam "A combinar". Lang inválido cai em PT default. Exportada na API.

### 2. `js/schema_proposta.test.js` — 20 testes novos

Cobertura: vazio/null/undefined/só-espaços/abc/negativo (string e numérico) → fallback; "0"/0 → "Pronta entrega"; "1"/"30"/60 → "N dias"; "15.7" → trunca via parseInt → "15 dias"; modo EN cobre todos os casos; lang inválido fallback PT.

**Suíte schema**: 85 → **105 testes**.

### 3. HTML — input Prazo no card do item

Grid Qtde/Unidade transformado em 3 colunas (Qtde/Unidade/Prazo). `<input type="number" id="sim-prazo-dias" min="0" step="1" placeholder="A combinar">` com tooltip explicativo da regra (vazio/0/N).

### 4. HTML — textarea Descrição pra Proposta

`<textarea id="sim-desc-proposta" rows="2">` posicionado após grid Qtde/Unidade/Prazo. Header com badge `🔁 auto` (visível em modo auto) + botão `↻ auto` (visível só após edição manual).

**Bug fixado durante implementação**: primeira tentativa usou `class="sim-row"` (flex horizontal com `max-width:55%` e `text-align:right` no input) — incompatível com textarea multilinha. Refatorado pra `<div>` block com `padding:9px 0; border-top:1px solid var(--border)` preservando separador visual do padrão `.sim-row`.

### 5. HTML — funções de auto-fill

```js
let _descPropAuto = true;  // flag módulo-level

_simDescPropostaMontarTexto()    // espelha lógica do coletor pra modo estruturado/livre
_simDescPropostaAtualizarUI()    // toggle badge/button visibility
simAutoDescProposta()            // idempotente, no-op se _pacoteRestaurando
simDescPropostaManual()          // oninput textarea → flag=false
simDescPropostaRestore()         // botão ↻ → flag=true + regenera
```

### 6. Triggers em campos técnicos

`oninput`/`onchange`/`onblur` de `sim-peca-aco`, `sim-peca-perfil`, `sim-peca-acabamento`, `sim-peca-de`, `sim-peca-l`, `sim-peca-texto` (modo livre), e fim de `simPecaModeChange` (toggle livre↔estruturado). Cada um chama `simAutoDescProposta()` defensivamente (`if(typeof ... === 'function')`).

### 7. Persistência — capture/restore

`SIM_SAVE_FIELDS` ganhou `sim-prazo-dias` e `sim-desc-proposta`. `pacoteCaptureFullState` captura `_descPropAuto` em `fields['_descPropAuto']`. `pacoteRestoreFullState` restaura no fim do finalize (após cascatas de simPontaToggle/setSellUnit) com fallback `true` pra snapshots legados.

**Proteção crítica**: `simAutoDescProposta` checa `_pacoteRestaurando` (do Bug 5) e é no-op durante restore. Sem isso, a chamada em cascata de `simPecaModeChange` regeneraria o textarea com campos ainda não restaurados, sobrescrevendo o conteúdo do snapshot.

## Lições e padrões

### 1. Inércia do CLAUDE.md
A sugestão "arrancar fase 3 proposta" no `Pra retomar em nova sessão` do CLAUDE.md ficou desatualizada após Fase 3+4+Refactor terem sido entregues. Lição: ao retomar com instrução do próprio CLAUDE.md, fazer descoberta dos logs antes de codar — Fase 3 estava fechada há 5 dias.

### 2. Padrão de auto-fill com desconexão
Mercosul (Fase 4f), VPP (Camada 11) e agora Descrição pra Proposta (Fase 2A.2) usam o mesmo padrão:
- Flag `_auto`/`_descPropAuto`/`dataset.auto`
- Auto-fill respeita flag (idempotente)
- Edição manual via `oninput` desconecta
- Botão de reversão regenera
- Proteção contra cascata de restore via flag `_pacoteRestaurando`

### 3. `class="sim-row"` é incompatível com textarea
CSS é flex horizontal com `max-width:55%` e `text-align:right` no input. Para campos multilinha, usar `<div>` block puro replicando `padding:9px 0; border-top:1px solid var(--border)`.

### 4. Função pura > regra inline no coletor
Primeira passagem do Prazo tinha a regra inline no `propostaColetarLinhas`. Refatorada pra `SP.formatPrazoDias` ganhou cobertura de teste em isolamento (20 testes), reuso e clareza. Coletor delega: `prazoStr = SP.formatPrazoDias(s['sim-prazo-dias'], _isExport ? 'en' : 'pt')`.
