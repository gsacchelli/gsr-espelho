# 2026-04-22 — W2.5 Shadow Bloqueante (proteção contra regressão silenciosa)

Promoção do shadow mode de diagnóstico (opt-in) a proteção bloqueante (default ON). Passo intermediário antes de W3 (wrapper fino faseado).

## Motivação

Motor bate bit-idêntico com HTML em 531 testes + fixtures reais 01-11. Dupla manutenção (simCalc + motor) é risco real: qualquer edição numa das bases sem espelho na outra cria regressão silenciosa. W2 tinha toast opt-in — Gustavo não necessariamente lembrava de ligar. W2.5 torna a proteção default, persistente, e com cobertura completa.

## Como testar

1. Abrir simulador. Toggle "Alertar divergência motor vs HTML (shadow bloqueante)" já deve estar marcado no Setup → Sistema.
2. Fazer uma cotação normal. Se motor bate (cenário sem bug), nenhum toast aparece. `window.SIM_LAST_CALC_MOTOR` populado.
3. Para testar divergência artificialmente: abrir DevTools → Application → Local Storage → deletar `sacchelli-simulador-setup`. F5. Fazer cotação. Toast deve aparecer no canto inferior direito e ficar lá até fechar manualmente.
4. Inspecionar `localStorage.getItem('afs_motor_divergencias')` pra ver histórico.

## Decisão arquitetural registrada

**Shadow bloqueante é proteção de regressão, não validação de correção.** Motor e HTML podem ter o mesmo bug — shadow só detecta quando UM deles muda sem o outro acompanhar. A autoridade continua sendo a bateria de testes do motor + fixtures reais capturadas em produção.
